# Compléter un traitement

## Un processus de création de traitement qui vous guide pas à pas

{% embed url="https://www.youtube.com/embed/videoseries?list=PL-EvtNdEiDxEzGBBTfGHy25vS6COmcgeQ&si=q8iJKz0VjemfjzbO" %}

L'application Dastra vous accompagne à chaque étape de la création d'un traitement, tout en vous laissant avancer à votre rythme. Des conseils sont proposés à chaque étape pour vous aider à respecter les exigences du RGPD.

## Qu'est-ce que le questionnaire de traitement Dastra ?

Le questionnaire de traitement recueille les informations nécessaires à un traitement. Il est découpé en sections, listées dans la navigation à gauche du traitement. À côté de la plupart des sections, la navigation indique le nombre d'éléments déjà saisis (finalités, jeux de données, destinataires, etc.). Utilisez les boutons **Suivant** et **Retour** en bas de page pour passer d'une section à l'autre.

Un traitement **Responsable de traitement** comporte 12 sections :

* **Général** - Saisissez les informations générales sur le traitement de données à caractère personnel, comme son nom, son unité organisationnelle et sa description.

{% content-ref url="general.md" %}
[general.md](general.md)
{% endcontent-ref %}

* **Parties prenantes** - Listez les utilisateurs en charge du traitement et les parties prenantes impliquées, comme les responsables conjoints ou le chargé de la mise en oeuvre du traitement.

{% content-ref url="stakeholders.md" %}
[stakeholders.md](stakeholders.md)
{% endcontent-ref %}

* **Finalités** - Décrivez les finalités du traitement et la base légale de chacune.

{% content-ref url="purposes.md" %}
[purposes.md](purposes.md)
{% endcontent-ref %}

* **Actifs** - Listez les actifs, internes ou externes à l'organisation (applications, logiciels, serveurs, etc.), qui supportent le traitement.

{% content-ref url="assets.md" %}
[assets.md](assets.md)
{% endcontent-ref %}

* **Données** - Listez les catégories de données traitées et leurs règles de conservation.

{% content-ref url="datasets.md" %}
[datasets.md](datasets.md)
{% endcontent-ref %}

* **Personnes concernées** - Listez les catégories de personnes concernées par le traitement.

{% content-ref url="data-subjects.md" %}
[data-subjects.md](data-subjects.md)
{% endcontent-ref %}

* **Droits des personnes** - Détaillez les modalités dont disposent les personnes concernées pour exercer chacun de leurs droits.

{% content-ref url="rights.md" %}
[rights.md](rights.md)
{% endcontent-ref %}

* **Destinataires** - Listez les destinataires des données. C'est aussi dans cette section que vous déclarez les transferts de données hors UE.

{% content-ref url="recipients/README.md" %}
[README.md](recipients/README.md)
{% endcontent-ref %}

{% content-ref url="recipients/transfers.md" %}
[transfers.md](recipients/transfers.md)
{% endcontent-ref %}

* **Mesures** - Décrivez les mesures de sécurité techniques et organisationnelles qui protègent les données.

{% content-ref url="security.md" %}
[security.md](security.md)
{% endcontent-ref %}

* **Analyse d'impact** - Évaluez si le traitement nécessite une analyse d'impact relative à la protection des données (AIPD).

{% content-ref url="impact-analysis.md" %}
[impact-analysis.md](impact-analysis.md)
{% endcontent-ref %}

* **Documentation** - Documentez le traitement et ajoutez tout document complémentaire (par exemple un code de déontologie, une politique de confidentialité, etc.).

{% content-ref url="documents.md" %}
[documents.md](documents.md)
{% endcontent-ref %}

* **Récapitulatif** - Relisez sur une seule page tout ce qui a été saisi dans les sections précédentes.

{% content-ref url="summary.md" %}
[summary.md](summary.md)
{% endcontent-ref %}

{% hint style="info" %}
Un traitement **Sous-traitant** suit le même parcours, avec deux différences : une section **Clients**, placée après **Données**, liste les clients pour le compte desquels vous traitez les données, et il n'y a pas de section **Analyse d'impact**. Consultez [le registre « Sous-traitant »](../processor.md).
{% endhint %}

Des champs personnalisés définis par votre organisation peuvent aussi apparaître dans chacune de ces sections.

## Les indicateurs des traitements

{% embed url="https://youtu.be/QAmXR4y2RYU" %}

Le questionnaire n'est pas le seul guide disponible pour remplir un traitement. Trois indicateurs vous aident à évaluer à quel point le traitement est complet, bien documenté et sensible. Ils sont affichés dans le panneau à droite du traitement et dans sa section **Récapitulatif** :

* **Progression**
* **Qualité**
* **Sensibilité**

#### Progression

Ce pourcentage est calculé à partir d'une série de contrôles qui vérifient que le traitement contient tous les éléments obligatoires : finalités, jeux de données avec leurs champs de données et leurs règles de conservation, catégories de personnes concernées, destinataires, mesures de sécurité et, pour un traitement en tant que sous-traitant, clients.

Ces éléments correspondent aux informations que l'article 30 du RGPD exige dans le registre des activités de traitement.

#### Qualité

Ce pourcentage est calculé à partir d'une série de contrôles sur la qualité des éléments saisis dans le formulaire. Ces contrôles vérifient par exemple que :

* chaque finalité a une base légale,
* au moins un actif est lié au traitement,
* l'exercice des droits des personnes concernées est décrit,
* la section **Analyse d'impact** a été complétée et, si une AIPD est requise, qu'elle a été réalisée,
* un utilisateur **Approbateur** est affecté au traitement,
* un transfert est déclaré pour chaque destinataire situé hors UE.

Ces critères vont au-delà de l'article 30 du RGPD et vous aident à anticiper d'autres obligations. Par exemple :

* réaliser une AIPD sur un traitement qui en nécessite une,
* identifier le logiciel qui supporte le traitement, ce qui vous indique qui en est l'éditeur. Vous pouvez alors identifier le sous-traitant et les éventuels transferts de données.

#### Sensibilité

Cet indicateur affiche le **niveau de sensibilité du traitement**.

Il est calculé automatiquement à partir des **critères suivants** :

* présence de données sensibles,
* présence de mineurs et/ou de personnes vulnérables parmi les personnes concernées,
* volume important de personnes concernées,
* présence d'un sous-traitant,
* présence d'un transfert vers un pays n'offrant pas un niveau de protection adéquat,
* nécessité de réaliser une AIPD.
