# Security measures

[**Article 30 1. g) of the GDPR**](https://gdpr-info.eu/art-30-gdpr/) requires the record to include, "_where possible, a general description of the technical and organisational security measures referred to in_ [_Article 32(1)_](https://gdpr-info.eu/art-32-gdpr/)".

Under [**Articles 5 1. f)**](https://gdpr-info.eu/art-5-gdpr/) and [**32**](https://gdpr-info.eu/art-32-gdpr/) of the GDPR, every data controller and processor must ensure the security of the data with measures appropriate to the level of risk.

What is a security measure? Any measure necessary to ensure the security and confidentiality of personal data. It can be, for example, a physical security measure, such as controlled access to the premises, or an IT security measure, such as an antivirus or a strong password policy for accessing the data.

For each processing of personal data, you must take the appropriate measures to ensure a level of security appropriate to the risk for the rights and freedoms of the data subjects (invasion of privacy, discrimination, etc.). The risk must not be assessed from the point of view of the company, but from the point of view of the data subjects.

Ensuring security means ensuring the confidentiality, integrity and availability of the data. Security measures must therefore prevent unauthorized access to the data, unwanted modification of the data and loss of the data.

For the measures to be appropriate to the risk, the risks must be assessed: identify the potential impacts on data security, the risk sources and the possible threats, and assess whether the existing measures are sufficient. If they are not, strengthen them.

## Add security measures to the processing activity

Security measures are entered in the **Measures** section of the processing activity.

1. In the **Measures** section, click **Attach security measure** and select the measures that apply to the processing activity.
2. If a measure does not exist yet, click **New security measure** to create it.

The measures are listed with their type (for example **Technical**, **Organizational**, **Physical** or **People**). For each measure, you can describe how it is applied to this processing activity in the **Specific details about the implementation in this processing** field.

Click a measure to view or edit it. From the **...** menu, you can also **Edit** it, open **More info** when a reference link is available, or **Delete** it from the processing activity.

{% hint style="info" %}
The security measures of an asset can also be added to the processing activity when you sync the asset's data from the [Assets](assets.md) section.
{% endhint %}

## Deployment status of the measures

Each security measure linked to the processing activity has a deployment status: **Non applicable**, **To be done**, **Planned**, **Being deployed** or **Deployed**. A measure added to the processing activity is set to **Deployed** by default.

Change the status of a measure from its row in the list of measures, or apply the same status to all the measures of the processing activity at once with the **Status** selector in the header of the list.
