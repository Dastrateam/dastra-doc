# Native applications

A native application does not display the web banner: it retrieves the banner configuration, displays its own consent screen, then sends the user's choices to Dastra. Both calls use the public API key.

{% hint style="info" %}
Depending on the hosting region of your organization, the address of the API changes (`api-bleu.dastra.eu` instead of `api.dastra.eu`). Use the one of your organization.
{% endhint %}

Requests without an `Origin` header, such as those of a native application, are accepted without checking the **Urls authorized (Allowed origins)**.

## Get the banner configuration

<mark style="color:blue;">`GET`</mark> `https://api.dastra.eu/v1/cookies/public/cookies-widget-settings/{id}?key={key}`

This endpoint returns the complete configuration of the banner.

#### Path parameters

| Name | Type | Description |
| --- | --- | --- |
| `id` | number | Identifier of the banner. |

#### Query parameters

| Name | Type | Description |
| --- | --- | --- |
| `key` | string | The public API key. |
| `culture` | string | The language of the configuration (`en`, `fr`, etc.). If missing, Dastra uses the `Accept-Language` header, then the first language of the banner. |
| `debug` | boolean | When `true`, no visit event is recorded. |

## Record consents

<mark style="color:green;">`POST`</mark> `https://api.dastra.eu/v1/cookies/public/collect/{id}?key={key}`

This method collects cookie consents.

#### Path parameters

| Name | Type | Description |
| --- | --- | --- |
| `id` | number | Identifier of the banner. |

#### Query parameters

| Name | Type | Description |
| --- | --- | --- |
| `key` | string | The public API key. |

#### Request body

| Name | Type | Description |
| --- | --- | --- |
| `type` | string | The event type: `Visit`, `Quit` or `Consents`. |
| `consents` | object | The list of the user's consents (see the example below). |
| `consentId` | string | The current consent identifier, if one has already been collected. |
| `referrer` | string | The address of the page or the screen the event comes from. |
| `userId` | string | Pseudonymous identifier of the user in your systems (optional). See [User identification](../identification.md). |

Example of a body:

```json
{
  "type": "Consents",
  "referrer": "my-app://settings/privacy",
  "userId": "{your_pseudonymous_user_id}",
  "consents": {
    "consentId": "6f47576e-5a0c-4219-8efe-331e72bab73a",
    "lang": "en-US",
    "versionKey": "36df80ee-235c-4485-b9e2-f28f5568f572",
    "cookieConsents": [
      {
        "id": "e213aca4-79b7-4b93-2bad-08d897969898",
        "name": "Google Analytics",
        "slug": "google-analytics",
        "consent": true,
        "date": "2026-10-12T14:00:04.133Z",
        "purpose": "Analytical"
      }
    ]
  }
}
```

The `200` response contains the identifier of the collected consent, for example `140f213b-de17-4572-99a7-5075ccbcbbec`. Keep it in the application for the next calls: it is the identifier of the proof of consent. Events sent by bots are ignored, and the proof is stored only if the **Save consent proof** option is enabled.
