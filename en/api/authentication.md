# Authentication

## Getting your API secret key

The Dastra REST API uses API keys to authenticate each request. You manage your keys in the **Api keys & MCP** page, which is reserved to organization owners. See [API key management](../features/settings/api-keys.md).

You can use an API key for a specific workspace or for the entire organization.

An API key gives access to your data, so keep it safe. Do not share your private key in public parts of applications, such as GitHub or client-side code.

An expired or unknown key is refused with status 401.

If you want to use OAuth2 authentication with the "authorization\_code" flow, enter the redirect URIs and the allowed CORS origins in the details panel of the key.

## API key (X-API-Key)&#x20;

The simplest way to authenticate is to use the HTTP header **X-API-Key** containing the private part of your API key, as in the example below:

```bash
curl -X 'GET' \
  'https://api.dastra.eu/me' \
  -H 'accept: */*' \
  -H 'X-API-Key: <your private key here>'

```

## OAuth2 "Authorization code" flow

### Authorization

The authorization phase is performed by calling the following URL:

```bash
https://account.dastra.eu/connect/authorize?
    response_type=code&
    client_id={YOUR_CLIENT_ID}&
    redirect_uri=https://YOUR_APP/callback&
    scope=api1+offline_access&
    state={STATE}
```

**Parameters**

| Parameter Name  | Description                                                                                                                                                                                                                                                                                     |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `response_type` | code                                                                                                                                                                                                                                                                                            |
| `client_id`     | The public key of your API key configured in your Dastra account                                                                                                                                                                                                                                |
| `redirect_uri`  | The URL configured in the Dastra API key. You will be automatically redirected to this page at the end of the authorization process                                                                                                                                                             |
| `scope`         | <p><code>api1</code> => mandatory<br><code>offline_access</code> => to obtain a refresh_token (long sessions)</p>                                                                                                                                                                               |
| `state`         | A random string generated by your application to prevent cross-site request forgery (CSRF) attacks. See [Mitigate CSRF Attacks With State Parameters](https://auth0.com/docs/protocols/oauth2/mitigate-csrf-attacks). Client libraries usually handle this automatically |

## OAuth2 "Client credentials" flow

### Authentication method

API authentication is based on the [OAuth2 protocol](https://oauth.net/2/) using the "Client credentials" flow. This authentication mode should only be used for server-to-server requests and must never be used on the client side (e.g., JavaScript SPA).

<figure><img src="../.gitbook/assets/api-authentication-scheam.svg" alt="Diagram of the Client credentials flow: your server requests a token from the Dastra identification server, then calls the API with that token"><figcaption><p>The Client credentials flow</p></figcaption></figure>

### Getting the token

`POST` `https://account.dastra.eu/connect/token`

Perform a token request using BASIC headers.

**Headers**

| Name          | Type                                       | Description |
| ------------- | ------------------------------------------ | ----------- |
| Authorization | Basic {base64("{PublicKey}:{PrivateKey}")} |             |

**Request Body**

| Name        | Type   | Description         |
| ----------- | ------ | ------------------- |
| grant\_type | string | client\_credentials |
| scope       | string | api1                |

Once you have retrieved an access\_token, you can call any REST API endpoint using this token as a "Bearer token".

For example, to get the list of your workspaces:

`GET` `https://api.dastra.eu/v1/Workspaces`

All requests must be made over [HTTPS](http://en.wikipedia.org/wiki/HTTP_Secure) and always from the server side. Requests without authentication will fail with error code 401.
